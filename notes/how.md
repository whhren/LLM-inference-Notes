# 大模型推理引擎到底如何执行请求

# 第一步初始化
假设我们使用1B的模型，请求有8个，这8个请求会组成一个Batch。 


# 第二步 计算 Q、K、V

我们使用 Llama 3.2 1B，继续沿用 8 个请求、Padding 后的输入矩阵。
# 输入矩阵

模型的 Hidden Size 是 2048，因此输入张量的形状为：
$ X:[8,6,2048] $

为了方便矩阵运算，可以合并前两个维度：
X:[48,2048]

# 计算 Q、K、V

每个 Token 的 2048 维向量，需要经过三个不同的线性变换，分别得到 Q、K、V。

计算 Q：

矩阵形状：
$ [48,2048]×[2048,2048]→[48,2048]$

计算 K：

矩阵形状：
$[48,2048]×[2048,512]→[48,512]$

计算 V：

矩阵形状：
$ [48,2048]×[2048,512]→[48,512]$ 

为什么 Q 的输出维度是 2048，而 K、V 只有 512？因为这个模型使用了 GQA（分组查询注意力）。

#  将结果拆分成多个头

注意：先完成线性变换，再根据注意力头的数量重新组织张量。

Llama 3.2 1B 的配置如下：
|矩阵	|头数	|每个头的维度	|总维度|
| ---: | ---: | ---: | ---: |
|Q	|32	|64	|2048|
|K	|8	|64	|512|
|V	|8	|64	|512|

因此，QKV 的形状变化是：
$ Q：[48, 2048] → [8, 6, 32, 64]$ 
$ K：[48, 512]  → [8, 6, 8, 64]$
$ V：[48, 512]  → [8, 6, 8, 64]$

这里的箭头表示重新组织数据的形状，不是再次进行矩阵乘法。

实际计算时，GPU 通常通过批量矩阵乘法，一次性计算所有 Token 的结果，不需要逐个 Token、逐个头地计算。
4. 为什么 K、V 只有 8 个头？

因为模型使用了 GQA：

4 个 Q 头共享 1 个 KV 头。

例如，Q 的 0～3 号头可以共享同一个 KV 头，Q 的 4～7 号头共享下一个 KV 头，以此类推。

这样可以减少 KV Cache 的存储量。
5. 计算完成后，哪些信息会被保留？

接下来会对 Q、K 应用 RoPE（旋转位置编码），然后进行 Attention 计算。

其中：

    Q：用于当前轮 Attention 计算，通常不需要长期缓存。
    K、V：写入 KV Cache，供后续生成 Token 时复用。
    请求边界、位置等元数据：继续保留，保证不同请求的计算相互隔离。

每一层都有自己的 KV Cache。Llama 3.2 1B 一共有 16 层，因此每个请求的历史 Token 都会在各层累积对应的 K、V。
